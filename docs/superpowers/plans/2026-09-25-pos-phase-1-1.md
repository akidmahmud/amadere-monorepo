# POS Phase 1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (the user chose Native inline execution). Steps use `- [ ]` checkboxes. Ledger: `2026-09-25-multi-store-pos-progress.md` (append "Phase 1.1" lines).

**Goal:** POS Settings (VAT), per-store HTML invoice templates, store-profit link to Accounts, 15 hardening fixes, and per-store sales and customer Excel exports.

**Architecture:** VAT lives in the `settings` key/value table (`pos.vat`). Invoice templates live in a new `pos_invoice_templates` table (row with `storeId null` = Default) and are rendered client-side by one pure `renderPosInvoice()` function. New report endpoints follow the existing CSV → `downloadCsvAsXlsx` pattern. The hardening fixes are local edits inside existing POS/stock/orders code.

**Tech Stack:** as Phase 1 (NestJS + Prisma, Next.js 16, Jest, `node --test`). `isomorphic-dompurify` is already a backend dependency.

**Spec:** `docs/superpowers/specs/2026-09-25-multi-store-pos-design.md` §12

## Global Constraints
- No git operations. Append to `H:\Amder Project\bug-fix-and-feature-edit.md` at the end.
- TDD: every backend behaviour and admin pure helper gets a failing test first. UI wiring is verified by `tsc`, lint and the Playwright E2E (`scratchpad/e2e.mjs`, extended).
- Dhaka days: `dhakaDayStart(day)` / `dhakaDayEnd(day)` / `dhakaDate(d)` from `apps/backend/src/modules/product-cost-history/dhaka-date.ts`.
- Tag values in invoices are HTML-escaped; the template HTML is sanitised on save.
- The website's Accounts VAT settings are not touched.

## Review Focus
1. **A stored invoice template carrying `<script>`/`onerror`:** it must be stripped on save and never run on the receipt page. (Task 3 test.)
2. **VAT disabled:** the till, quote, receipt and order all show 0 VAT, and the total equals the net. (Task 1 test.)
3. **Return clicked twice or from two tabs:** exactly one refund and one restock. (Task 5 test.)
4. **A sale at 01:00 Dhaka time:** it counts in that Dhaka day's "Today" and reports. (Task 5 test.)
5. **A customer sheet over a range with no sales:** a header-only file, not an error. (Task 7 test.)

```prisma
model PosInvoiceTemplate {
  id          Int      @id @default(autoincrement())

  html        String   @db.Text
  updatedById Int?     @map("updated_by_id")
```

### Task 5: Hardening (backend)
**Files:**
- Modify `pos-sale.service.ts`, `pos-catalog.service.ts`, `pos-reports.service.ts`, `stores/*`, `stock/*`, `orders/orders.service.ts`, `products/products.service.ts`.
- Create `pos/dhaka-range.ts` (+spec).

**Steps (each: failing spec, then implement):**
- [ ] **(1) Dhaka days.** `dhakaRange(from?: string, to?: string)`: default today in Dhaka, returns `{gte, lt}`. Used by `recent`, `stats`, `sales`, `profit`, and the exports. Spec: `2026-09-25` gives `gte` `2026-09-24T18:00Z`; 01:00 Dhaka falls inside.
- [ ] **(2)+(3) Returns.** `returnSale` first runs `tx.order.updateMany({where:{id, status:'COMPLETED'}, data:{status:'RETURNED', returnedAt: now}})`; if the count is not 1 it throws 409. Only then does it restock via `StockService` (RETURN), write status history, and refund.
  - Orders-service path: `updateStatus` sets `returnedAt` when moving to RETURNED/PARTIALLY_RETURNED.
  - `returnSale` no longer calls `updateStatus` (that would double-restock). It does the restock itself, and the store-routing helper stays for Order Manager use.
  - Spec: the claim count 0 means 409, no stock move and no refund.
- [ ] **(4) Tendered cash.** `create()` stores `tenderedAmount` for CASH. Spec asserts it is on `order.create` data.
- [ ] **(5) Inactive store.** `StoresService.assertActive(storeId)` is called by sale, stock-in, adjust, transfer create (both sides) and receive, and throws 400 "Store is inactive". Spec.
- [ ] **(6) Transfer approval scope.** `approve(scope, id)` applies `assertSide`-like logic to either side. Spec.
- [ ] **(7) CSV safety.** `toCsv` prefixes `'` when a cell starts with one of `= + - @ \t \r`. Spec.
- [ ] **(8) Store list privacy.** `list(canSeeStaff)` returns `staffCount` always and `staff` only when allowed. The controller uses `@Can()`. Spec.
- [ ] **(11) Duplicate.** Duplicating a store-only product copies `storeId` and keeps `ADMIN_ONLY`. Spec in the products spec.
- [ ] **(13) Lookup.** `lookup` is exact only: barcode, then SKU; otherwise 404. Update the catalog spec.
- [ ] **(14) Other store's product.** `StockService.move` refuses a product whose `storeId` is set and differs from the move's store. Spec.
- [ ] **(15) Re-completion.** In `updateStatus`, the COMMIT branch runs `decrementStockOnly` only if `order.status` ∈ RELEASE_ON_CANCEL (the order's current status is a released one); otherwise it does nothing when `wasEverCompleted`. Spec: COMPLETED → PROCESSING → COMPLETED does not decrement.

  - An empty range gives a header-only CSV (`toCsv` of `[]` still emits the header when given column names — add `toCsv(rows, columns?)`).
- [ ] Spec for salesLines: one row per order item, including variant and payment.
